# AI Working Instructions — Trading Management Platform

**نسخه:** 1.1.0  
**وضعیت:** بازسازی‌شده بر اساس تصمیمات تأییدشده مالک پروژه  
**زبان اسناد اصلی:** فارسی  
**مخزن:** https://github.com/elvito2808/Trading-Management-Platform

## هدف
این پوشه مرجع اصلی روش همکاری عامل‌های هوش مصنوعی با این مخزن است. اسناد با Markdown ساده نوشته شده‌اند تا به نرم‌افزار خاصی وابسته نباشند. وجود فایل‌ها به‌تنهایی تضمین نمی‌کند هر محصول هوش مصنوعی آن‌ها را خودکار بارگذاری کند؛ فایل‌های راهنمای ریشه مخزن نقطه کشف را برای محیط‌های پشتیبانی‌شده فراهم می‌کنند. عامل باید پیش از شروع، اسناد مربوط را واقعاً باز کند و بخواند.

## اسناد الزامی
1. [GLOBAL_INSTRUCTIONS.md](GLOBAL_INSTRUCTIONS.md) — برای تمام درخواست‌ها.
2. [RESEARCH_PROTOCOL.md](RESEARCH_PROTOCOL.md) — برای تحقیق، جست‌وجو، بررسی فنی، مقایسه و تحلیل مبتنی بر شواهد.
3. [EXECUTION_PROTOCOL.md](EXECUTION_PROTOCOL.md) — برای توسعه، کدنویسی، تغییر فایل، تست، رفع خطا، Git و تحویل پروژه.

در مأموریت‌های ترکیبی، تمام اسناد مرتبط باید خوانده شوند.

## ترتیب اعمال
1. محدودیت‌های ایمنی، سیاست‌های پلتفرم و قانون؛
2. درخواست صریح و جدید مالک، در محدوده مجاز؛
3. قواعد اختصاصی و امنیتی مخزن، از جمله این اسناد و docs/agents/؛
4. دستورالعمل عمومی و نقش عامل؛
5. پیش‌فرض‌های ابزار.

هیچ سندی مجوز معامله واقعی، انتقال دارایی، افشای اسرار، تغییر production یا Merge بدون مجوز صریح و متناسب ایجاد نمی‌کند.

## شروع مأموریت
عامل باید:
- اسناد لازم را از شاخه/نسخه واقعی مخزن بخواند؛
- نسخه یا commit اسناد را ثبت کند؛
- README.md، PROGRESS.md، docs/agents/README.md و docs/agents/IMPLEMENTATION_STATE.md را در صورت ارتباط بررسی کند؛
- وضعیت زنده GitHub، شاخه، commit و PRهای مرتبط را با مستندات تطبیق دهد؛
- نوع مأموریت را Research، Execution، Hybrid یا General تعیین کند؛
- محدودیت دسترسی، اطلاعات ناموجود و تأییدهای لازم را پیش از تغییر اعلام کند.

صرف دیدن نام فایل یا وجود لینک به معنی خواندن آن نیست.

## مستندات و ادامه کار
- این پوشه روش کار را تعریف می‌کند، نه وضعیت لحظه‌ای پیاده‌سازی را.
- برای وضعیت چندعاملی از docs/agents/IMPLEMENTATION_STATE.md استفاده کنید.
- نتیجه، شواهد، تست‌ها، خطاها، تصمیمات، محدودیت‌ها و اقدام بعدی را در مستندات پروژه ثبت کنید.
- پیش از توقف قابل پیش‌بینی، تا حد امکان HANDOFF تهیه کنید. ساخت HANDOFF پیش از قطع ناگهانی یا محدودیت غیرمنتظره قابل تضمین نیست؛ بنابراین مستندات باید در طول کار نیز به‌روز باشند.

## سازگاری ابزارها
محیط‌هایی که فایل‌های راهنمای مخزن را خودکار بارگذاری نمی‌کنند، باید فایل‌های لازم را صریحاً از همین مخزن دریافت کنند. اگر عامل امکان دسترسی به فایل‌ها را ندارد، باید محدودیت را اعلام کند و وانمود نکند دستورالعمل‌ها را اجرا کرده است.
